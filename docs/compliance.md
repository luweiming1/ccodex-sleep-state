# 合规与使用边界

> 这不是法律意见，也不是“加一段免责声明就没有风险”的承诺。使用地、运营方式、实际功能、发布和宣传内容都会影响判断。面向公众持续提供软件或经营相关服务前，应请熟悉当地电信、网络与数据合规的律师审查。

## 项目做什么，不做什么

本项目是用户在本机运行的连接、配置和状态管理工具。用户自行配置有权使用的账号、上游与网络连接。

- 不提供、出售、推荐或内置可用的代理节点和订阅服务；不代售网络接入，不保证任一跨境线路合规。
- 不修改系统代理、路由、DNS 或 TUN；导入订阅时不执行其规则、代理组及系统网络配置。
- 不增加账号额度，不解除上游限制，不以换 IP、换模型、回收节点或重新配置规避 401/403/429 暂停。
- 不自动重放生成请求，不将一条可能已经计费的失败请求伪装成“从未发生”；不保证使用 state 后回答更好。
- 仅使用用户有权使用的凭据；不收集账号库，不公开完整 state、代理凭据或私有订阅地址。

“用户自己提供”并不自动证明来源或使用方式合法。不得把导入功能用于无权使用的账号、代理或网络，也不应将本工具对外包装成承诺绕过限制的服务。

## 中国境内需要特别审查什么

2024 年修订的《中华人民共和国计算机信息网络国际联网管理暂行规定》仍对国际联网的国际出入口信道，以及接入网络经营许可/非经营批准作出要求。具体应核对其第六条、第八条及适用业务事实，不能仅凭“本工具不卖节点”得出当然豁免的结论。[海关总署公开的修订文本](http://kjs.customs.gov.cn/kjs/2024-09/26/article_2025121606124025624.html)

实际审查至少应覆盖：

1. 软件只是使用现有连接，还是被用于组织、提供、转售网络接入或跨境连接服务。
2. 发布包包含的网络功能、默认开启行为、推广文案与实际运营是否一致。
3. 订阅、账号、模型请求和个人数据经过谁的服务器；相关服务商授权、条款、数据处理和跨境义务是否适用。
4. 付费、分成、推广、售后或其他商业关联是否改变业务性质。不能仅靠改名或页面标签排除实质义务。

这里没有对某个具体代理、服务商或经营模式作合法性认定；本项目也不能替用户或运营方取得所需许可。

## 已做的约束与尚未做到的隔离

| 约束 | 当前实现 | 不能据此推断 |
| --- | --- | --- |
| 默认本机管理 | 管理入口、口令和同源限制，避免直接开放管理面板 | 把端口暴露公网就仍然安全 |
| 用户自带连接 | 不分发预置节点；支持外部 HTTP/HTTPS/SOCKS5 端点 | 任意来源自动合规 |
| 外部代理模式 | 运行时拒绝内嵌隧道协议节点，仍可用直连或外部代理 | 发行包已经剔除内核，或属于“合规专版” |
| 有界采集 | 超时、间隔、次数限制和暂停规则；固定可用 state 减少无谓探测 | 能保证不触发风控，或已量化节省额度 |
| 实际出口可控 | 明确选择兼容、独立随机或用户固定 | 能伪造任意 IP，或两个节点必有不同公网 IP |
| 日志与诊断最小化 | 常规诊断不公开凭据、正文、私有订阅与完整 state | 原数据目录或备份也可以随意分享 |

**当前构建仍打包内嵌核心及相关依赖。** 外部代理模式不是构建层面的删除。若发行方需要不包含隧道实现的精简分发，需要另做独立构建、依赖检查、功能验收与法律审查；本轮没有把这种版本冒称为已完成。

## 反馈问题时保护好哪些东西

优先使用面板的脱敏诊断。截图前检查自定义节点标签；不要公开以下内容：API key、OAuth 登录材料、完整 state、订阅链接、节点密码、原始会话正文、整个服务数据目录或配置备份。

发现认证失败先在 Codex 或服务商处处理，遇到限流先等待。反馈时只给运行版本、脱敏状态、发生步骤和必要错误码；不要为了“验收通过”持续重复请求或改换身份。
